# 产品设计草案

## 目标与范围

在用户现有终端旁显示一棵目录树，同一目录中的 Agent 会话集中展示。用户继续在原终端工作，通过侧栏快速判断哪些会话在执行、哪些需要处理，并切换到目标会话。

已确定采用 tmux 方案：在当前 tmux window 左侧创建专用 pane 承载 TUI。首版以 macOS 上实际运行的 tmux 为目标，覆盖所连接 server／socket 内当前有 client 附着的 session、window 的 pane，包括普通 shell；没有 client 附着但当前进程树仍有非 shell 程序的 pane 同样纳入，包括 Claude Code／Codex／CodeBuddy／Pi 与普通前台或后台服务，不因 detached 隐藏仍存活的 Agent，重启侧栏后也适用。仅靠历史启动命令不能证明 Agent 仍存活；空闲 detached shell 不自动纳入，其他 socket 和 tmux 外部终端不自动纳入。**保留规则**：侧栏自身的导航会 `switch-client`，把 client 从原 session 移走使其变为 detached；为此本次侧栏运行期间曾附着过的 session 会一直保留，避免用户「选了一个窗口，原来那个就没了」。这里的「聚合」指逻辑分组，不搬移用户 pane；侧栏本身会占用列宽并改变当前 window 的布局。侧栏绑定启动它的 tmux client，跟随原生 window／session 切换，只迁移自建 pane，保留当前输入焦点。

## 侧栏信息与交互

```text
 会话  ·  3 个
──────────────────────────────
▾ [agent-tree]  ~/workspace  2
  ├─ Codex
  └─ Shell
▾ [kzz-radar]   ~/workspace  1
  └─ Codex
```

会话名称左侧使用两列宽、一行画布的原有 PNG 图标，与三行条目的中间行名称对齐；条目第三行显示最后活动时间：当天为「最后活动 · HH:MM」，跨日增加月日，跨年显示完整日期；无记录显示「暂无活动记录」。以当前屏幕变化作为本次运行中的活动证据，首次采样、单纯刷新或焦点变化不赋予新的时间，不伪造历史活动。Codex、Claude Code、CodeBuddy、Pi 与 Shell 的资源保持原样，未知身份保留 `?`。图片支持 iTerm2／tmux，不支持时回退 `O`／`C`／`B`／`P`／`$`，名称保持可读；五种图片按实例各上传一次，位置随 tmux 标记重绘，滚动、折叠、焦点与跨窗口切换不重复上传。

树线进一步校正为目录 → 会话 → 会话信息：根树干位于第 4 列，贯穿各条目上方与非末条目的信息行；会话行以 `├──┬`／`└──┬` 连接，信息行以 `└───` 从第 7 列分叉，末条目之后根树干结束。会话图标改为两列 × 一行，只在名称行显示，源 PNG 不变，展示完整图片，不发送来源裁取参数；避免三行图片遮住分级树线。目录与分支使用透明线条 PNG，分支徽标以半圆端帽包住底色；无图片时保留字符回退。

顶部采用用户指定参考图的 One 标识与 “All agents in one.” 副标题。正常可见图片模式且侧栏至少 26 列、24 行时使用本地 640 × 160 PNG，在 24 列 × 3 行虚拟画布内居中；其他情况显示 “❯▪ One” 文字，短终端再隐藏副标题。图片可见性改变时维持同尺寸顶部高度，避免列表跳动。Logo 单独缓存与释放，不改变会话图标身份或导航功能。

暗色主题采用紫黑底 `#171726`、灰蓝次要文字、绿色目录名、浅紫灰加粗会话名称和蓝色当前会话竖线。默认宽度为窗口的 20%，`--width` 可覆盖。顶部「当前任务」与横线展示原有会话总数；目录行保留方括号名称、会话数与 `[+]`，可用空间足够时显示粉色 Git 分支徽标，只读分组仓库的 HEAD，支持 worktree 与 detached HEAD；失败隐藏，分支不参与分组或排序。父路径在宽栏显示。选中背景覆盖三行条目区域，图片模式使用两侧一列 × 三行的透明圆角 PNG，左侧包含连续蓝线；右边缘避开终端最后一列，防止组合标记错位。不支持图片时使用连续竖线与矩形背景，不覆盖正文信息；当前会话与键盘浏览位置继续独立。行按列宽截断，中文占两列。

状态在名称右侧显示小圆点，宽栏追加 Working／Waiting／Ready／Unknown；窄栏先隐藏状态文字，过窄时优先名称。蓝点每 0.6 秒明暗交替，其余黄／绿／灰点静态；普通 Shell 不显示状态点。识别与采样规则保持原样，Ready 仅表示输入框就绪，不承诺成功。首次扫描前仍显示「正在扫描会话…」。保留底部键位和错误提示，不添加没有数据支撑的「最近任务」区。

进入其他 session 的会话时会执行 tmux `switch-client`：把你发起操作的那个终端一起切到目标 session，原 session 变为 detached。这是「定位到对应终端」的固有代价——一个 tmux client 同一时刻只能看一个 session。跳转多次后可能出现两个终端停在同一个 session 上，此时侧栏对该 session 只列一条（两边看的是同一个窗口）。轻量的浏览（`↑`／`↓`）绝不触发它。

**退出侧栏时必须把被带走的终端送回它原来的 session**（仅当它仍停在被带去的位置，用户自己切换过则不干预）。这样避免导航把用户终端长期留在别的 session；仍存活的 Agent 与普通服务即使 detached 也必须可见，空闲 detached shell 仍遵循附着与本次保留规则。

支持展开／折叠与当前会话高亮。原生切换 window／session／pane 后，高亮同步到当前用户 pane，自动展开对应分组并滚动到所在行；返回侧栏浏览时保留用户选择，其他 client 的活动不抢走侧栏。`↑`／`↓` 只在可见子会话行之间移动高亮，跳过路径根节点与已折叠的子会话，到达首尾时停留，不改变当前视图；`Enter`（或鼠标点击会话）**进入选中会话**--切换视图并把输入焦点交给目标 pane；`→` 与 `Esc` 与 `Enter` 等价，不向 Agent 发送这些按键；`n` 或路径节点右侧的 `[+]` 按钮在对应目录下新建一个 session（默认 shell），建好后把 client 与侧栏一起带过去，按钮点击只触发新建，不触发会话导航或折叠；目录未知或只读浏览模式不显示按钮。这是侧栏唯一会新建终端的操作，且只新增 session、不改动既有 pane。选中目录组只展开／折叠，不切换终端。侧栏旁的用户 pane 全部关闭（如 shell 执行 `exit`）时自动补位：优先迁移到被关会话所在目录分组的第一个会话并把焦点交给新 pane，该分组不在了取整个列表的第一个；列表为空则退出侧栏，session 与终端交由 tmux 自然收摊。数据刷新、初次加载和程序恢复选择不触发导航（上述补位除外）；状态更新不抢焦点、不突然改变行顺序。纯文本快照显示完整路径与状态文本；状态来源保留在模型字段，当前没有详情面板。首次进入无数据时区分「没有 Agent」「无法读取目录」「宿主未连接」，不统一显示为空。

## 流畅度与一体感目标

2026-10-14 根据参考产品截图确定体验方向：侧栏与主体保持稳定的视觉关系，点击后及时反馈，输入焦点切换不让整个侧栏呈现明显的活动／非活动跳变。截图不作为参考产品实际性能或实现方式的证据。

第一批已实现后台宿主操作、导航反馈、当前会话与浏览位置分离及侧栏／底栏同色；当前会话保持蓝色竖线和背景，浏览其他条目使用灰色 `›`。本节保留后续体验目标，真实宿主外观与长期稳定性待验收；尚未修改宿主原生非活动 pane 外观或 tmux 分隔线。

- 当前打开会话保持独立标记；上下键浏览另一条目时，用户仍能辨认右侧显示的是哪一个会话。导航中的反馈与成功打开状态分开，失败不把目标显示为已经打开。
- 焦点交给 CLI 后，侧栏的背景、图标与当前会话标记保持稳定；焦点仍按真实输入归属处理，不通过伪装焦点向错误 pane 发送输入。宿主原生外观的可控范围须实机确认。
- 会话发现、宿主查询和状态采样变慢或失败时，侧栏仍可浏览、折叠和退出；快速连续点击最终进入最后有效目标，失败给出明确提示。
- 第一批保留现有 tmux 会话与迁移侧栏方式，不承诺完全消除主体尺寸变化和重绘。固定侧栏或独立终端宿主只作后续备选，不纳入当前实现承诺。

执行顺序、代码证据、测量与失败路径验收统一见 [架构优化方案](/Users/mac/workspace/agent-tree/docs/architecture.md#流畅度与一体感优化方案) 。不复制参考产品的品牌、额外信息模块或未提出的功能。

## 目录归属

默认按 **Git 仓库根目录**分组：从会话工作目录逐级向上查找 `.git`，命中即以该目录成组，因此同一仓库下不同子目录的会话（如 `kzz-radar` 与 `kzz-radar/web`）聚在一起，项目名也稳定显示为仓库名。只做文件系统判断，不调用 `git`。不在任何仓库内时退回本机规范化的完整工作目录；软链接解析到同一真实目录后自然合并，不可解析时保留原路径并标注。相同 basename 的不同路径不能合并。未知目录进入「目录未知」，不能猜成侧栏启动目录。家目录本身不作为仓库根，避免 dotfiles 配置把所有家目录下的会话并成一组。

worktree 与 submodule 的 `.git` 是文件而非目录，同样算命中，因此各自独立成组。会话工作目录发生变化后更新归属；Agent 内部目录无法读取时沿用最近可信目录并标注来源。远程主机相同路径不能与本地或其他主机合并，首版不保证远程发现。

## 核心验收场景

1. 同目录分别打开 Claude Code 与 Codex，归入同一组；同种 Agent 的两次启动不合并成一条。
2. 两个不同完整路径具有相同目录名，保持独立；软链接入口按规则合并；父子目录与 worktree 独立。
3. 在启动侧栏前已开的会话、新开的 window／pane 和同一 tmux server 内跨 session 会话都能被发现；无权限时明确说明覆盖范围。
4. Agent 退出回到 shell 后移除 Agent 标识；会话关闭后清理条目，焦点切换遇到过期 ID 不发送输入。
5. 历史输出含「等待确认」但当前实际执行时，不错误报警；长时间无输出不直接判为完成。
6. 多个 window、session 和 tmux client 场景，避免重复条目；导航只作用于发起操作的 client，不切换其他 client 的 session。共享 session 的当前 window 变化可能影响其他 client，需验证并明确提示。
7. 中文、空格路径、窄屏、无 Nerd Font、宿主断连与重连均有明确回退。
