## 已确定的行为

1. 当前 window 左侧专用 pane 展示 TUI，数据范围为启动上下文指定的同一 tmux server／socket，跨 session、window 聚合；排除自建侧栏。
2. 按规范化完整目录分组；同名异路径不合并，软链接可解析时合并，父子目录与 worktree 独立，未知目录单独展示。
3. 每个 Agent pane 是独立条目，同种 Agent 不合并。普通 shell 不显示成 Agent；无法可靠识别的候选项明确显示未知。
4. 鼠标点击或键盘上下选中会话，立即展示目标 window／session 的内容，输入焦点留在侧栏，继续上下选择不输入到 Agent。右方向键或 Esc 才交出焦点，不向目标转发导航按键。
5. 目录行只展开／折叠。初始加载、自动刷新和恢复选择不触发导航，不抢焦点。
6. 无可信执行状态时显示「状态未知」；本 Goal 不区分执行、空闲与等待确认，不采集或存储完整对话。
7. 导航标识包含 server 身份及稳定 pane ID，明确发起操作的 client；过期目标提示并保持安全位置，不能凭 window 序号导航。
8. 退出只清理本实例创建的侧栏；用户进程与 pane 保留，用户期间的布局调整不能被旧快照覆盖。

## 检查点 1：验证宿主与交互可行性

依赖：实际启动开发后，读取本机 tmux 版本及命令帮助；涉及变化的接口核对当前官方手册。

工作：在独立 socket 创建测试环境，验证 pane 枚举、cwd、进程信息、稳定 ID 与侧栏自排除；验证同 window、跨 window 和跨 session 的即时导航、侧栏继续接收键盘、交出焦点与退出。比较按 window 创建和迁移自建侧栏方案，记录对布局、多个 client 和退出的影响。

预期：证明「目标视图变化、侧栏仍保留输入焦点」可以实现；选择一种最小方案，明确布局共享的实际影响。共享 session 的 window 选择可能影响其他 client，必须验证并写明，不能承诺 client 完全隔离。

失败路径：tmux 不可用、版本不支持、socket 失效、client 无法唯一确定、目标 pane 已删除、window 太窄。均需明确错误且不改变用户会话。关键交互若无法成立，记录证据及可选方案，先解决方向歧义再实施，不自行降级成回车导航。

## 检查点 2：实现发现、识别与目录树

依赖：检查点 1 的技术栈、目录职责与宿主操作方案确定。

工作：实现启动上下文校验、快照获取、Claude Code／Codex 身份检测、目录规范化、树结构及稳定排序。保持单进程与内存快照，除非有验证过的必要性，不引入数据库或常驻 daemon。

验证：

- 同目录不同 Agent、同种 Agent 多 pane 分别保留；跨 session 链接的同一 pane 不重复。
- basename 相同、父子目录、worktree、软链接、中文与空格路径按既定规则归属。
- shell／node 等通用进程名、输出中的 Agent 名字、同名非 Agent 程序不误识别。
- Agent 退出返回 shell、pane 新增／关闭、cwd 变化、权限缺失、无法解析路径均更新或明确降级。
- 普通 shell 即使没有 Agent 也给出准确空状态；侧栏不进入自身列表。

交付：发现与分组模块、必要单元测试、可浏览的 TUI；真实 Agent 检测另以本地可用 CLI 验证。模拟进程只能验证解析分支，不能替代真实身份识别验收。

## 检查点 3：实现即时导航与生命周期

依赖：检查点 2 的稳定会话键与树选择模型。

工作：实现鼠标和键盘选中即切换、焦点保留、右方向键／Esc 交出焦点、目录折叠、选中高亮及失效目标提示。自建侧栏使用明确的实例所有权，处理重复启动、多个侧栏实例、正常退出与异常终止。

验证：

- 连续上下切换无需回车；目标终端未收到导航字符，侧栏可继续操作。
- 跨 window／session 后侧栏仍存在且交互一致；交出焦点定位到选中的 pane。
- 刷新、条目删除和排序变化不产生意外导航；旧 generation 结果不覆盖新数据。
- 多 client 不误切其他 client 的 session；共享 window／布局的实际影响与设计记录一致。
- 窄屏、resize、socket 断开、目标关闭、退出与崩溃不结束用户进程；仅清理有所有权的侧栏资源。
- 未被用户改动的布局退出后尽量恢复；已改动布局保持用户新结构，不强制恢复旧快照。

交付：完整基础闭环、导航与清理回归证据、异常残留说明及安全恢复方式。

交付结果（2026-10-04 14:58，已完成）：新增 `sidebar.py`（生命周期与导航），TUI 接入选中即切换、`→`／`Esc` 交出焦点与鼠标点击映射。隔离端到端验证 `verify_cp3.py` 22 项与 `verify_cp3_resilience.py` 14 项全部通过；单元测试扩至 119 项。验证覆盖创建、迁移、焦点、退出、崩溃、窄屏、重复启动、多 client 隔离与 `--in-pane` 接管拒绝，用户 pane 与 agent 进程全程保留，未绑定快捷键也未改动 tmux 全局配置。过程中修复 argparse help 含 `%` 导致启动器崩溃、`--in-pane` 可能接管用户 pane、启动器未捕获 tmux 错误，以及集成测试残留 socket 四项缺陷。证据见 [验证记录](/Users/mac/workspace/agent-tree/docs/validation.md) 。异常残留与恢复方式：侧栏进程结束时 tmux 自动关闭其 pane；若因 `remain-on-exit` 等配置残留，可按 pane 级标记 `@agent_tree_sidebar` 识别并手动 `kill-pane`。
